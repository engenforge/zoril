# One provenance model for the store and return rules

This note is the design that the hardening series implements: Z-0047 (the origin sets, in place), Z-0048 (the store and return rules, behind `--provenance`), Z-0010 and Z-0057 (one call summary, then its `.zri` form), Z-0011 (declarations checked against the body) and Z-0012 (the flag on, the old classifiers deleted). Its liveness part is in place for writes into a local's own fields; writes through a pointer to the local are Z-0044. It describes what decides an escape today, why that design keeps leaving holes open, the model that replaces it, how each known hole maps onto the model, what the model will newly reject, and how it lands.

## 1. What decides an escape today

Four mechanisms, at two IR levels, answer overlapping questions:

- **Flow-sensitive borrows (`ActiveBorrow`: borrower local, borrowed place)**
  - Where: `src/check_zir.zrl`, ZIR
  - Decides: conflicts and liveness inside the frame: use after `free`/`reset`/`@drop`/move, the strict reborrow rule, arena epochs
  - Summary it writes: none
- **The buffer-escape rule (`check_borrow_escapes_frame`, `local_storage_external`, `local_is_external_target`, `place_outlives_frame`, `rvalue_storage_external`, `is_collection_type_name`)**
  - Where: `src/check_zir.zrl`, ZIR
  - Decides: whether a returned or stored value carries a borrow of heap storage the frame owns (a collection, a box, an arena) and whether the destination outlives the frame
  - Summary it writes: `stores_storage`/`store_targets` (`storage_walk_zir`)
- **The region verifier (`storage_facts`, `storage_param`, `check_call_stores_stack`, `check_borrows_claim`, `check_fn_value`)**
  - Where: `src/verify.zrl`, ZIL
  - Decides: whether a _stack_ address escapes; whether `#[borrows]`/`#[stores]` claims hold
  - Summary it writes: `ret_storage`, and `stores_storage` again (**overwriting** the ZIR one)
- **The interprocedural summary pass**
  - Where: `src/summary_pass.zrl`, ZIL
  - Decides: `escape`/`stash`/`ret_stack` per parameter, for calls and the `.zri`
  - Summary it writes: `summary_escape`/`summary_stash`/`summary_storage`

`ret_ties` (which parameters a returned reference borrows) is a fifth input, set in `src/driver/module.zrl` from `#[borrows(..)]` or the elision default, never from the body.

So one property - _an address that is only valid while this frame (or something it owns) is live must not leave it_ - is split by kind of storage (heap owned by a local: ZIR; stack slot: ZIL), checked by two analyses with different precision, and summarised three times in 64-bit masks that are combined by overwriting.

## 2. Why the holes keep coming

The probes named here are in `bench/safety_matrix/probes/`; `doc/spec/safety_model.md` lists the ones still open under "Known gaps".

1. **Unknown means allowed.** The classifiers return `false` ("not external", "not carrying") for any shape they do not recognise: a chain of more than 8 copies (`gap_10`), a call returning a struct rather than an enum (`gap_08`), a closure call (`gap_29`), a field write (`gap_09`), a whole assignment to a closure capture (`gap_12`), a type nested in an enum (`gap_13`, `gap_18`, `gap_23`, `gap_36`). Fixing a shape teaches the classifier that shape; the next unrecognised one stays open.
2. **Definitions are chased backwards, per whole local.** `local_storage_external` and `local_is_external_target` search the function for the `let` or whole assignment that defined a local and recurse, so a field write (`sm.r = out`, `w.s = view`), a second assignment, or a value that arrives through a loop is not seen.
3. **Summaries disagree and are computed once.** Three writers, an `i != j` filter (`gap_07`), no bit for parameter 64 onwards (`gap_27`, `gap_33`), no fixpoint over recursive calls (`gap_28`), declarations (`#[borrows]`, the `&self` default) trusted instead of checked (`gap_30`), the later writer replacing the earlier, and the ZIL writer blind to an aggregate passed by value (`gap_32`).
4. **Name lists.** `is_collection_type_name` decides by name which types own storage.

## 3. The model

**Origins.** Every address a value can hold has an origin:

- `Frame(L)` - the stack slot of local `L`, or storage `L` owns (a `Vec`/`String`/`HashMap` buffer, a `Box`, an `Arena`'s blocks, a closure environment). By-value parameters are locals. Inside a closure, an _owned_ capture is `Frame(c)` too: its storage dies when the closure frees or grows it, whatever the frame does.
- `Param(i)` - memory reached _through_ parameter `i` (the referent of a reference parameter, what a by-value aggregate parameter's fields point to). A closure's by-reference capture is a `Param`-like origin of the environment.
- `Static` - globals, string literals, other `static` data.
- `Env` - inside a closure body, the environment its captures are read from: memory of the closure's creator, so external like a `Param`.
- `Raw` - an address `@ptr_from_int` made from an integer, which the programmer vouched for in `unsafe` code (_Raw operations_ below). In a value it is exempt from the store and return rules; as a destination it is external, like `Unknown`.
- `Unknown` - anything the analysis cannot classify. **`Unknown` is treated as `Frame` when it is the value and as external when it is the destination**, so it always rejects.

**Two sets per local.** `O(L)`: the origins of addresses `L` holds (in any field: field-insensitive). `S(L)`: the origins of the storage `L` owns - `Frame(L)` for a fresh `Vec::new()`/`box`, the arena argument's origins for `Vec::new_in(a)` (from the constructor's summary), `S(src)` when `L` is moved or copied from `src`. Only a type that owns storage gets an `S` (_Ownership_ below). Both are computed **forwards** to a fixpoint over all statements (flow-insensitive: a local's set is the union over every assignment; a reassigned local keeps its earlier origins, which is conservative and documented).

**Transfer.** For `x.p1..pn = rv` (including `n = 0`, any projections, not through a deref): `O(x) |= O(rv)`, `S(x) |= S(rv)`. Reading any projection of `x` yields `O(x)`. `&p`/`&mut p` of a frame place yields `Frame(p.base)`; through a reference `r`, it yields `O(r)`. A call yields, for each argument `i` the summary ties to the result: `Frame`/address origins of the argument if the result points into its own storage (`ret_storage`), `S(arg) | O(arg)` if it points to what the argument reaches (`ret_ties`). A call through a `fn` value (`CallPtr`) yields `Unknown`, and counts as storing every reference argument into every other; the callee's environment is one of those arguments (_Closure environments_ below). An `extern "C"` call with no `#[borrows(..)]` yields `{Static}` (_Scalars, casts and `extern`_ below).

**The rules.**

- _Store_: `*r = v`, `r.f = v`, `r[i] = v` through a reference `r` (or into a closure's capture, or a global): if the destination's origins `O(r)` contain anything but `Frame` origins of this frame - a `Param`, a `Static`, a capture environment, or `Unknown` - then `O(v)` must contain no `Frame` and no `Unknown`.
- _Destination reach_: the destination origins a store, a call or an unknown call checks are not one hop. A `Frame(L)` in them adds `S(L)` (the storage `L` owns, so `Vec::new_in(caller_arena)` is external) and, when `L`'s type can hold a mutable handle, `O(L)`, followed to a fixpoint. The leaf handles are `&mut`, `[mut T]` and a `fn` value; every other type answers for what it contains: a `Box`/`BoxMut`, a raw pointer, `&T`, `[T]` and an aggregate recurse into their element or field types, so a `Vec<str>` (`*mut str` inside) holds no handle and a `Vec<Slot>` with `Slot { out: &mut [i32] }` does. A `Box` is not a leaf: it owns its allocation, which `S(b)` already reaches, and counting it would make `set_box(&mut b, arena_slice)` follow `O(b)` and refuse the `Box` twin of `v.push(arena_str)`. So a callee or closure writing through `*r.out`, with `r = &w` and `w` holding the caller's `&mut`, has the destination `Param` of `w.out` (`gap_47`), however many local references stand between (`gap_48`). The reach does not follow `O(L)` for a type that holds only shared views: `v.push("lit")` puts `Static` in `O(v)`, and an unconditional reach from `&mut v` would see that `Static` and refuse the safe `v.push(arena_str)`.
- _Return_: `O(ret)` must contain no `Frame` and no `Unknown`.
- _Where they apply_: every function body, an `unsafe fn`'s included (Z-0063). Z-0048 exempted every `unsafe fn` body, because one that makes an address from an integer (`mmap_or_trap`, `arena_init_result`) returned `Unknown`, which the return rule always refuses; that left the rest of such a body unchecked, and a frame view stored through a closure in an `unsafe fn` compiled and read a freed arena (`tests/language/memory/provenance/unsafe_fn_body_checked_refused.zrl`). The exemption is now the narrow one of _Raw operations_.
- _Call_: for each `i -> j` in the callee's store summary, the caller applies the store rule with value `O(arg_i)` (or `S(arg_i) | O(arg_i)` when the callee stores what `i` reaches) and destination `O(arg_j)`; `j` may equal `i`. An unknown call (`CallPtr`, or a summary with `storage_known` false) checks every argument against every other, itself included; for `CallPtr(callee, args)` the arguments are `args` plus `os_through(O(callee))`. Every destination here is taken with the destination reach above, so a direct call `write_slot(r, s)` with `fn write_slot(r: &Slot, s: [i32]) { *r.out = s; }` stays refused once Z-0012 deletes the buffer-escape rule of §1, which refuses it today.

**Liveness** stays where it is: the flow-sensitive `ActiveBorrow` set keeps deciding use after `free`/`reset`/`@drop`/move and the strict reborrow rule, with one change - a write into a projection of `x` adds the right-hand side's borrows to `x` (field-insensitive), instead of dropping them. This change is in place for a write into a local's own fields; a write that reaches the local through a pointer (a local `&mut`, a `&mut` parameter, `self` in a method, `*b` on a `Box`) does not add them yet (Z-0044).

**The summary** is the same analysis read at the function's edges. Each parameter `i` is seeded with two origins: `ParamAddr(i)`, the parameter's own slot (`&c.n` for a parameter `c`), and `ParamContents(i)`, the memory reached through it (`c.v` in `take_ref`); the single `Param(i)` used elsewhere in this note is the two together. `ret_storage` = the `ParamAddr`s in `O(ret)`; `ret_ties` = the `ParamContents` in `O(ret)`; `ret_fresh` = whether `S(ret)` holds a `Frame` or `Unknown` origin, so the caller's result owns fresh storage (_Details the transfer needs_); `stores i -> j` = every store whose value carries `Param(i)` into a destination carrying `Param(j)` (or a global), kept as pairs, `j` equal to `i` included. One computation, on ZIR (Z-0010). Each body's summary is written when its origin pass ends; the bodies of a recursive cycle (the strongly connected components of the call graph, found on the lowering stack by Tarjan's low-links) keep their ZIR until the cycle is complete and are iterated from empty summaries to a fixpoint (the sets only grow), so a recursive cycle no longer spreads `Unknown` through `storage_known` false. A compact record of each body was rejected: one restricted to parameter origins cannot replay a cycle callee's write into a local of its caller (Z-0059). Bit 63 means "parameter 63 or later" in both directions. The `.zri` (Z-0057) carries the pairwise `i -> j` edges, with the overflow bit on either side, `ret_storage` and `ret_ties` as separate masks, and the `ret_fresh` bit: two flat `stores`/`into` masks would pair every stored parameter with every target, conflating `i -> j, k -> l` with `i -> l`.

**The summary as built (Z-0010, B2.1a; the cycles' fixpoint, Z-0059).** Each body, an `unsafe fn`'s too (Z-0070), writes its summary to its function when its origin pass ends, and a later call reads it in place of the old masks. A callee is lowered inside its caller, so a call to a body still on the lowering stack closes a recursive cycle (Z-0059): it reads an empty summary, the cycle's bodies keep their ZIR, and when the outermost of them finishes they are recomputed with one another's summaries until none grows (each joined with the last), then checked once with the final ones. A member's first summary, from its own pass, is only a lower bound for the calls lowered before the cycle completes, which the fixpoint revisits; `--emit-origins` prints a member's sets from the final check. A cycle closed through a `fn` value is not one the lowering stack sees: such a call stays an unknown call. Parameter `i` is seeded with `ParamAddr(i)`, what argument `i` itself holds; a read through `ParamAddr` or `ParamContents` memory yields `ParamContents`. At the call, `ParamAddr(i)` is the argument's own origins and `ParamContents(i)` what is reached through it. The store edges are kept per stored value (its code, then the targets' `ParamAddr` and `ParamContents` bits and a global bit), recorded at every store through a pointer, every summarised call and every unknown call. The rules this needs, each of which a probe or golden test shows is needed:

- A `ParamContents(j)` target is the destination reach of argument `j`'s own origins (_The rules_ above), not every read through it: a callee writes only through what it could write through, so the `Static` of a literal already in a `Vec<[u8]>` makes no `v.push` external.
- An edge's value written into local `L` leaves out the `Frame` origins of the storage `L` owns: an address into `S(L)`, held by `L`, moves with `L`. Without it `self.cap = grow_cap(self.cap)` in `Vec.push` puts a `Vec`'s own buffer into `O(v)`, and every `return v` of a pushed-to `Vec` is refused. Storage in a local arena gains nothing from this: the arena tie puts `Frame(a)` into `O(L)` itself.
- A value stored by value moves, and the storage it owns goes with it: the `Frame` origins in its `S` that are not also in its `O` leave the value an edge records, the value the call store rule checks (for a `ParamAddr` or a `ParamContents` value at a call, and for a declared or summary-less store), and the value written into a target local's `O`; they join the target owner's `S` instead. This is the in-body store rule's reading (it checks `O` only), carried to summaries: without it `v.push(Vec.new())` into a caller's `Vec` records `store Unknown`, and a builder that pushes a fresh owner into a local `Vec` and returns it is refused by the return rule. A `Frame` in both sets stays: a collection in a local arena holds `Frame(a)` as an address too. A callee's `ParamContents` never names a by-value parameter's own buffer (that is `Frame` of the parameter in the callee, which the in-body rule sees), so the moved storage leaves that value as well, and what the buffer holds stays.
- An integer stored in the body records no edge (Z-0071, a decided boundary; a declared `#[stores(..)]` edge is recorded whatever the stored argument's type, so `put(slot, (&x) as *i32 as usize)` through `#[stores(n -> slot)]`, or `v.push(..)` of such an integer into a `Vec<usize>`, is still refused at the call: an over-refusal, kept until a task prunes integer arguments there with its own differential). Narrow scalars carry no origins already; the pointer-width ones (`usize`, `isize`, `u64`, `i64`) may carry an address (_Scalars, casts and `extern`_), but an edge for them made a callee's bookkeeping (`arena.offset = .. + size`) an address of whatever its operands were read from. What is given up: a callee storing a caller's frame address, cast to an integer, into the caller's memory is not seen at the call (`int_store_through_call_accepted.zrl`), and a later `@ptr_from_int` of it yields `Raw`. Making a pointer of an integer needs `unsafe`, so safe code cannot use the route, and the store rule still checks such a store in the body that makes it (`int_store_in_body_refused.zrl`).
- An unknown call's edges carry what its arguments reach, not the `Unknown` it adds to the caller's own sets: a `fn` value's body was checked where it was made, and an `Unknown` edge would refuse every caller handing it a closure.
- For an integer result, a `ParamContents` tie does not count (a `ParamAddr` tie, `p as usize`, does), including one a `#[borrows(..)]` declares: sets that are not per field cannot tell `self.len` from a pointer field, and making an address of an integer needs `unsafe` either way. Z-0011 has to match this exception.
- Under a body summary an arena tie adds the arena argument's own origins to `S`, never what the arena struct holds, which includes the C memory of its blocks (`Static`).
- A slice's `len` holds no origins: it is a count, and without this `self.len = self.len + other.len` reads as storing `other` into `self`.
- Until Z-0011 checks declarations against bodies, a declared `#[borrows(..)]` or `#[stores(..)]` adds to what the body proves rather than being replaced by it, which is also the end state (_Checked contracts_ below), except for the integer rule above: a store or copy through a bare `extern` such as `memcpy` (`Vec.clone_in`) is invisible to the body, and a declaration may be wider than it. A narrowing `#[borrows()]` adds nothing, so it no longer launders a tie.

**Checked contracts.** `#[borrows(..)]`, `#[stores(..)]` and the `&self` default are **checked** against what the body proves (Z-0011). A declaration may list more than the body does (a wider public contract), never less: narrowing in safe code is a compile error, and an exemption is an explicit, reviewed `unsafe` interior with a `// SAFETY:` comment. For a function with a body, the effective ties and stores are the union of what the body proves and any declaration (a wider declaration is a public contract and takes effect; a narrower one is the error above). For a bodyless item (`extern`, trait signatures, `.zri` imports) the declarations and the `&self` elision default apply as written. The ZIL verifier keeps its stack-address check as a second net that may only _add_ rejections; it no longer writes a summary.

**Deleted:** `local_storage_external`, `local_is_external_target`, `rvalue_is_external_target`, `place_outlives_frame`, `rvalue_storage_external`, the depth limits, `is_collection_type_name` (ownership comes from the type's structure, _Ownership_ below), the `i != j` and `& !target` filters, `storage_walk_zir`'s separate mask logic, and the summary role of `storage_facts` and `summary_pass.zrl` (the `.zri` fields stay, filled from the one summary).

**Reads through a reference.** The memory a dereference reaches has the origins of the pointer read: `O(r) ∪ S(r)` for a local `r`. A read from memory with origins `M` yields, for each `Frame(L)` in `M`, what `L` holds (`O(L)`) and what it owns (`S(L)`), kept apart as a direct read keeps them, so a value moved out of an enum payload or a box stays an owner; a `Param`, `Static`, `Env` or `Unknown` origin in `M` stays itself. A call reads its tied arguments the same way: for an argument in `ret_storage` the result has the argument's own origins (it points into the argument), and for one in `ret_ties` it has what is reached through the argument - one or more reads through it when it is a reference, the argument's origins and everything reached from them otherwise - with `O` and `S` merged, since the callee may return a view of either. So `let r = &c; take_ref(r)`, where `take_ref` returns the view `c` holds, yields `O(c)`, the view's origin, and not `Frame(c)`: Z-0045's reproducer, and its forms through an identity call (`take_ref(id_ref(&c))`, where `id_ref` is in `ret_storage`) and a join, all give the view's `Param`. Its twin, `let r = &v; r.as_slice()` for a local `Vec` `v`, yields the `Frame` origin of the storage `v` owns. The golden tests under `tests/language/memory/origins/` (`read_through_*`) check both; read literally, as `O(r)` itself, the rule gives `Frame(c)` back and they fail. An index is read as codegen indexes (Z-0068): it first goes through every pointer and box layer, like a dereference; an array is then indexed in place; a `Vec` (not reached through a `&mut` or `*mut`, which codegen indexes as an array of `Vec`s) through its buffer pointer, so the element is memory the `Vec` reaches, `O(v) ∪ S(v)` for a local `v`, as for a slice; anything else reached through a pointer is pointer arithmetic over that memory, of the same type. Only an index the walk cannot type adds `Unknown` (`vec_index_field.zrl`, `rawptr_index_field.zrl`).

**Details the transfer needs.** A closure body reads its captures through the environment (`GetEnv`), whose origin is `Env`: the caller's, external like a `Param`. A capturing closure's value is the address of its environment struct, so it holds `O(env)` (_Closure environments_ below). A write through a pointer adds the value to every local whose `Frame` origin the destination memory has, so `let r = &mut w; r.s = v` grows `O(w)`. An aggregate the callee takes by value arrives as a pointer to a temporary (`ILParam.by_ref`) and is read as the value. A cast reinterprets its operand, so its value holds what the operand owns as well as what it holds: `b as *i32` for a box `b` is an address into `S(b)`. A box (`Box<T>`, `BoxMut<T>`) is an owning wrapper of its value, not a pointer: it is move-only, `O(b)` holds what its `T` holds and `S(b)` its allocation, so `*b` is a projection of `b` like a field. A place through `*b` (`(*b).s`) reads `O(b)` and `S(b)` as a direct read does, and a write into it is a projected write into `b`; only a reference to the box (`&mut b`, `&mut *b`) is a pointer crossed. The `S` of an owning call result (a result type that owns, _Ownership_ below) is not "the tied arguments, else fresh". Only a tied argument whose type can reach an `Arena` (or its raw form, a `*mut ArenaHeader`, as `Vec.new_in_raw(arena)` takes) adds its origins to `S`, so `Vec.new_in(a)` and `String.with_capacity(a, n)` own `S = O(a)` while `"lit"` (`Static`) or a tied `cap: usize` never enter `S`. The result also owns fresh storage of this frame (the call's own `Frame`) when its type is or contains by value a `Box`/`BoxMut` or a `Drop` type, when no tied argument can reach an `Arena`, or when the callee's summary says its returned `S` holds a `Frame` or `Unknown` origin (Z-0010, so `fn f(a: &Arena) -> Vec<i32> { return Vec.new(); }` is fresh). Z-0047's `os_call` took `S` from the tied arguments alone: `make_pair(s) -> Result<(Arena, [i32]), i32>` gave `pair` `S={Param(1)}` with no `Frame`, so a `Vec` built in `pair.0`'s arena would read as external once Z-0010 computes `new_in`'s ties from its body; and `make_vec(s: [i32]) -> Vec<[i32]>` gave `S={Param(0)}`; Z-0048 changed both (`tests/language/memory/origins/call_result_*.zrl`). Z-0047's `os_walk` stepped through a box as through a pointer, so `(*b).s` read through it a second time: with `b = wrap(v.as_slice())` and `fn wrap(s: [i32]) -> Box<W> { return box W { s: s }; }`, `x = (*b).s` got `O={}`, and `*out = x` was refused only by the buffer-escape rule of §1; Z-0048 changed the walk (`box_wrap_read.zrl`). A call with a store summary adds what each stored argument reaches to every local each target argument reaches (until Z-0010's pairwise edges, the summary's masks are not paired, so each stored argument meets each target, itself included); a call with no usable summary stores everything every argument reaches, and `Unknown`, into everything any argument reaches; for `CallPtr` the callee's environment counts as an argument. Either way a stored value grows `S(L)` of a target only by what the value owns: `v.push("lit")` adds `Static` to `O(v)`, never to `S(v)` (Z-0047's `os_summary_store_effects` and `os_unknown_call_effects` passed one set as both and grew `S` too; Z-0048 separated them). A summary is unusable when `storage_known` is false, which includes every callee whose own storage walk read a callee in a recursive cycle, until the one summary of Z-0010 replaces it.

**Ownership (decided 2026-11-03).** A type owns storage if and only if it is `Box<T>`, implements `Drop` (`Arena`, `BufWriter`, `File`, `FileLock`), is one of the four standard-library collections designated as owners until collections get a `Drop` of their own (`Vec`, `String`, `ByteVec`, `HashMap`), or contains an owning type by value. A raw pointer (`*T`, `*mut T`) owns nothing, so `Lexer`, `Parser`, `ArenaMark` and `Args` are not owners: a view read through a `&Lexer` carries no `Frame(lex)`. The designation is by type, not by name lookup at each use, and goes away with collection `Drop`. Z-0047's `os_owns` counted raw pointers and did not see `Drop` or the four collections; Z-0048 brought it to this rule (`Drop` is a function `T::drop` in the module).

**Closure environments.** A closure value is `FuncAddr(f, env)`, the code address and the address of its environment struct. `FuncAddr(_, env)` copies `O(env)` (`{Frame(env_struct)}`, the environment being a local of the creating frame) rather than adding a fresh `Frame` of the pointer temporary, so a read through the closure value reaches what the captures hold. `CallPtr(callee, args)` treats `os_through(O(callee))`, the memory the environment reaches, as an implicit read-write argument beside `args`, both in the unknown-call store effects and in the unknown-call store check. Inside the closure body nothing changes: captures are read through `GetEnv` with origin `Env`, external. So the check happens at the call in the creating frame, where the captures' origins are known. On `gap_11` the environment holds `out` (`Param`) and `routed` (a `Frame` view), and the call stores one into the other: refused. On its safe twin, `fn safe(out: &mut [i32], view: [i32]) { let mut cl = || { *out = view; }; cl(); }`, it holds two `Param`s: accepted. On `gap_45` the environment holds `r` (`Frame(w)`) and `s` (a `Frame(a)` view), so the call's effects give `O(w)` `Frame(a)` and `Unknown`, and `*out = w.s` is refused.

**Scalars, casts and `extern` (decided 2026-11-03).** A cast and pointer-width arithmetic preserve origins: a value of `usize`, `isize`, `u64` or `i64` can carry an address, including one that `Vec.get` returns. A narrow scalar (an integer of 32 bits or fewer, `bool`, `char`, a float, unit) clears them: a local of such a type gets no origins. `PtrFromInt` adds `Raw` to whatever its operand carried (_Raw operations_). A call to an `extern "C"` function with no `#[borrows(..)]` yields `{Static}`: C memory is outside the frame, and a safe wrapper that returns a view of one of its arguments says so with `#[borrows(..)]`, which is what ties the result back. It has no store effects unless `#[stores(..)]` declares them. An `extern` signature takes only primitives, `fd<..>` and raw pointers (no reference, slice, `Box`, `fn` value or aggregate), so a safe caller cannot hand it a frame address that a check would follow, and calling one already needs `unsafe`. So an unannotated `extern` is a known summary, not an unknown call: Z-0047's `os_call` took it as unknown (`known = f.storage_known && !(f.is_extern && !f.has_summary)`), which gave `zoril_allocator_alloc` the result `Unknown` and ran the unknown-call effects on `memcpy` and `memset`; Z-0048 changed that before its rules read it.

**Raw operations (decided 2026-11-05, Z-0063).** A `@syscall` result is the kernel's integer and carries none of its arguments' origins: an argument is read by the kernel during the call, and an address the kernel hands back (`mmap`) becomes a pointer only through `@ptr_from_int`. `@ptr_from_int` adds `Raw`, not `Unknown`, to whatever the integer carried. `Raw` is the programmer's claim, made in `unsafe` code, that the address is valid: the return and store rules do not count it in a value (`arena_init` returns a box holding one, `raw_open` returns the result of `open(2)` called on a frame buffer), and every other origin of the same value is still checked, so a frame address cast to an integer and back stays `Frame` and is refused. As memory, `Raw` is outside the frame: a frame address stored through a raw pointer is refused. The summary keeps `Raw` in the result flags, so a caller of a function returning such a pointer sees the same (`raw_return_store_through_refused.zrl`). An `unsafe fn` writes its summary like any body (Z-0070): its callers read it, not the old masks. Measured with `--provenance=warn`: `src/main.zrl` 195 -> 196, `tools/zbuild` 30 -> 40, `tools/zman` 39 -> 0 (zman's were the old masks giving `split_raw`'s result fresh storage of the caller's frame). The summaries carry two imprecisions to callers: a local `Arena`'s mapping is `Raw`, so memory reached through it is a destination outside the frame (P2, Z-0076), and the allocator's `mmap` path gives every arena allocation `Raw` (P1, Z-0077); together they refuse 42 programs of `tests/` and the probes under `--provenance` that were accepted before. `#[fresh]` (Z-0078) is the author's claim, on an `unsafe fn` returning a raw pointer, that each call returns memory no other live pointer reaches (an allocator's anonymous `mmap`); Z-0076 reads it to give such a result fresh storage of the caller instead of `Raw`, and until then it changes no origin check.

**Closures and `fn` pointers (deferred).** A `fn` value and a capturing closure share one type, so a call through either is `Unknown`. Whether to split them (for example, a downward-only closure type whose calls are summarized) waits for Z-0049's measurement after the Z-0010 fixpoint: how many over-rejections and open gaps come from `fn`-value and closure calls. Monomorphized `Fn` traits are rejected as the alternative.

## 4. Every known hole against the model

Closed probes are fixed today by the classifiers this model deletes; the model must keep them closed. Open probes are `known_gap` today.

- **`gap_01`, `gap_02`, `gap_03`** (closed)
  - Shape: a view carried in a struct field, tuple slot or array slot of a local, then stored out
  - Caught by: field-insensitive transfer: `O(w)` gets `Frame(v)`
- **`gap_34`, `gap_35`** (closed); **`gap_37`, `gap_38`, `gap_39`, `gap_43`** (open)
  - Shape: `w.s = view; a.reset(); w.s[0]`; the same with the write made through a local `&mut`, a `&mut` parameter, `self`, or `*b` on a `Box`
  - Caught by: liveness: a projected write adds the borrow to `w`; through a pointer, to the local the pointer refers to (Z-0044)
- **`gap_40`, `gap_41`, `gap_42`** (open)
  - Shape: a frame view written into a local struct's field through a local `&mut`, by a callee through its `&mut` parameter, or into a field of a `Box`'s contents, then stored out (`*out = w.s`)
  - Caught by: a write through a pointer adds the value to every local the destination memory has a `Frame` of (`os_write_memory`), and a call's store summary does the same for its targets (`os_summary_store_effects`), so `O(w)` carries the view's `Frame` and the store out is refused (Z-0048). For the box, `(*b).s = v.as_slice()` is a projected write into `b` (a box is a value wrapper, §3), so `O(b)` grows directly; through `&mut b` or `&mut *b` it grows by `os_write_memory`
- **`gap_12`** (closed)
  - Shape: a whole assignment to an owned capture
  - Caught by: the destination is the capture environment (external)
- **`gap_11`, `gap_45`** (open)
  - Shape: a closure stores a frame view through a captured `&mut` parameter; a closure writes a frame view into a field of a local through a captured local `&mut`, and the field is then stored out
  - Caught by: the closure call in the creating frame, with the environment as an implicit argument (_Closure environments_ in §3). Not by the closure body: there `out` and `routed` both have `O={Env}`, exactly as on the safe twin `|| { *out = view; }` over two parameters, so a body-side rule cannot tell them apart.
- **`gap_47`, `gap_48`** (open)
  - Shape: a closure captures `r = &w` (or `rr = &r`), where the local struct `w` holds the caller's `&mut`, and stores a frame view through `*r.out`
  - Caught by: the destination reach of §3's rules. The environment holds `Frame(w)` (or `Frame(r)`), and the caller's `Param` is two (or three) hops away in `O(w)`, so a single read through the environment misses it; following `O(L)` for every reached local whose type can hold a mutable handle finds it at any depth. The direct-call twin `write_slot(r, s)` is refused today only by the buffer-escape rule of §1 and needs the same reach once Z-0012 deletes that.
- **`gap_46`** (open)
  - Shape: a store through a `&mut` returned by a call, when the call's result is the function's last local
  - Caught by: not the model: `storage_walk_zir` and `note_call_stores_zir` index the 0-based `locals` with a 1-based `Local.id`, so the store summary the rules read stays empty. Fixed in the existing code (Z-0056) before Z-0048 reads that summary.
- **`gap_31`** (closed)
  - Shape: `Bundle { tag, a }` or `(a, tag)` makes the arena look external
  - Caught by: `S` per local, not "any operand": `S(b) = Frame(a)`
- **`gap_08`** (closed)
  - Shape: a call returning a struct holding a `&mut`
  - Caught by: `O(sm)` from the call's ties = `Param(h)`
- **`gap_29`** (open)
  - Shape: a closure call returning a captured `&mut`
  - Caught by: a `fn`-value result is `Unknown`, external as a destination
- **`gap_09`** (closed)
  - Shape: `sm.r = out; *sm.r = view`
  - Caught by: forward transfer into a projection
- **`gap_10`** (closed)
  - Shape: ten copies of `out`
  - Caught by: a fixpoint has no depth limit
- **`gap_07`** (open)
  - Shape: one tuple parameter holds destination and value
  - Caught by: `i -> i` allowed in the summary
- **`gap_28`** (open)
  - Shape: mutual recursion
  - Caught by: the strongly-connected-component fixpoint
- **`gap_17`, `gap_22`** (closed); **`gap_27`, `gap_33`** (open)
  - Shape: the value is the 65th parameter
  - Caught by: the overflow bit
- **`gap_04`, `gap_05`, `gap_06`, `gap_30`** (closed); **`gap_44`** (open)
  - Shape: a method, `&self` method or trait method returning its argument; a `#[borrows()]` function returning its argument; a `#[borrows()]` method returning a view its receiver holds, read after an arena reset
  - Caught by: ties computed from the body; declarations checked (Z-0011 refuses the narrowing `#[borrows()]` in safe code)
- **`gap_14`, `gap_15`, `gap_19`, `gap_20`, `gap_24`, `gap_25`** (closed)
  - Shape: a stack reference, element reference or stack-capturing closure stored out through a by-value struct, a closure parameter or a closure call

## 5. What it will newly reject (to measure, not assumed)

- A local reassigned from a frame view to a `static` slice, then stored out (flow-insensitive sets).
- A struct with one frame-owned field and one parameter-derived field, whose parameter-derived field is stored out (field-insensitive sets). If common, make `O` field-sensitive for direct fields only.
- By-value owning parameters (`v: Vec<i32>`) are `Frame(v)`. Today they count as external, so a view of one stored out is accepted (`gap_32`); under the model it is rejected. Today it is a leak, not a crash, because collections are not freed at scope end; with a `Box` parameter it is a stack-address error already.
- Every `#[borrows()]` and `#[stores(..)]` that declares less than the body does. The tree has 82 `#[borrows()]` declarations (`src/`, `stdlib/`, `tools/`), such as `Lexer.text_from`, whose result is a view of source text in the compilation's arena and so outlives the lexer it is read through; each is either proved by the body or becomes an explicit, reviewed exemption.

## 6. How it lands

Behind a flag. The new analysis runs beside the old one under `--provenance`, and reports in warning mode (`--provenance=warn`) on the whole tree (`src/`, `stdlib/`, `tools/`, `corpus/`). The store grid (`scripts/check_store_grid.sh`) is the definition of done: every unsafe cell rejected, the over-rejected twins listed. Then the flag becomes the default and the old classifiers are deleted. In tasks:

- **Z-0047 (B1.1, done):** the origin sets on ZIR, dumped by `--emit-origins`, read by no rule then.
- **Z-0048 (B1.2):** structural ownership and the closure-environment transfer, then the return and store rules behind the flag, reading the existing summaries.
- **Z-0010 (B2.1a), Z-0059 (B2.1b):** the one summary in memory (`ParamAddr`/`ParamContents`, per-body summaries, the overflow bit, `i -> i`), then the fixpoint over recursive cycles, which keeps their bodies' ZIR.
- **Z-0057 (B2.2):** the pairwise edges and the two return masks in the `.zri`; the ZIL summaries retired. As built: `#[summary(..)]` gains `ret_addr`, `ret_contents`, `ret_flags`, `ret_fresh`, `decl_stores`/`decl_into` (the author's `#[stores(..)]` masks, which the importer cannot read from a body) and, per edge in order, `edge` (the stored value's code), `edge_addr`, `edge_contents`, `edge_global`. An importer that finds `ret_addr` marks the function's summary known and reads it as it reads a body's; an older interface has none, and keeps the old masks. An `unsafe fn` writes one too since Z-0070 (`iface_attrs/prov_*_unsafe_fn*.zrl`). The old verifier masks still run beside it until Z-0012, so a safe pairwise call is still refused by them: the gain shows as unsafe calls the old masks accepted (the modular grid under `--provenance`: 125 accepted unsafe cells to 0). The ZIL summary writers are retired with the old classifiers in Z-0012.
- **Z-0049 (B1.3):** what `--provenance=warn` refuses in the tree, after the fixpoint so recursive cycles do not swamp it.
- **Z-0011 (B3):** declarations checked, and the exemptions made explicit.
- **Z-0044 (B0.1):** liveness for a write that reaches a local through a pointer, reusing Z-0010's store edges.
- **Z-0012 (B4):** fix what Z-0049 and Z-0011 found, make the flag the default, delete the old classifiers and the name list.

The self-hosting compiler is itself checked by the new rules, so Z-0049 and Z-0011 measure `src/` first. The ZIL stack-address check stays throughout, so no step weakens what is caught today.

## 7. The alternative

**Three cross-cutting fixes inside the current code:** every classifier fails closed; projected writes and aggregates use the union; one summary with a fixpoint, the overflow bit, `i -> i`, checked declarations and the ZIL verifier add-only. It keeps the backward definition chase, which cannot see a field write without becoming a forward analysis, and it keeps heap and stack escapes in two analyses. Its three fixes converge on this model's analysis anyway (a forward, field-insensitive, fail-closed fact per local) while leaving the four mechanisms and the overlapping summaries in place, so the model replaces them instead.
