    ```sh
    #!/bin/sh
    # usage: measure.sh <sha>   (run from the main tree's root; one at a time)
    # Builds <sha> in a scratch worktree if it is not built yet, measures it with today's harness
    # (today's scripts/ and bench/cross_lang/ beside that tree's build/ and stdlib/), and appends
    # the run to bench/records/ as a `backfill` row of gate_history.tsv plus its speed rows.
    set -u
    sha=$1
    R=$(pwd)
    B=$R/build/backfill
    wt=$B/wt-$sha
    H=$B/h-$sha
    T=$B/t-$sha
    if [ ! -x "$wt/build/zbuild" ]; then
        [ -d "$wt" ] || git worktree add --detach "$wt" "$sha" > "$B/$sha.wt.log" 2>&1 || { echo "$sha: worktree failed"; exit 1; }
        (cd "$wt" && make > "$B/$sha.make.log" 2>&1) || { echo "$sha: build failed (see $B/$sha.make.log)"; exit 1; }
    fi
    [ "${BUILD_ONLY:-0}" -eq 1 ] && { echo "$sha: built"; exit 0; }
    rm -rf "$H" "$T"; mkdir -p "$H/bench" "$T"
    cp -R "$R/scripts" "$H/scripts"
    cp -R "$R/bench/cross_lang" "$H/bench/cross_lang"
    for f in config.mk config.local.mk config.local.sh; do [ -f "$R/$f" ] && cp "$R/$f" "$H/$f"; done
    ln -s "$wt/build" "$H/build"
    ln -s "$wt/stdlib" "$H/stdlib"
    mkdir -p "$wt/build/bench"
    [ -d "$wt/build/bench/compare" ] || cp -R "$R/build/bench/compare" "$wt/build/bench/compare" 2>/dev/null
    GATE_HISTORY=$T/g.tsv SPEED_HISTORY=$T/s.tsv METRICS_FILE=$T/m.tsv sh "$H/scripts/bench_threshold_check.sh" > "$B/$sha.bench.log" 2>&1
    rc=$?
    if [ $rc -ne 0 ] || [ ! -s "$T/g.tsv" ]; then echo "$sha: bench failed rc=$rc (see $B/$sha.bench.log)"; exit 1; fi
    row=$(awk -F'\t' -v OFS='\t' -v c="$sha" 'NR==2 { $2=c; $12="backfill"; $13="backfill"; print }' "$T/g.tsv")
    [ -n "$row" ] || { echo "$sha: no gate row"; exit 1; }
    if [ "${DRY:-0}" -eq 1 ]; then printf '%s\n' "$row" | cut -f1-4,11-17; exit 0; fi
    printf '%s\n' "$row" >> "$R/bench/records/gate_history.tsv"
    awk -F'\t' -v OFS='\t' -v c="$sha" 'NR>1 { $2=c; print }' "$T/s.tsv" >> "$R/bench/records/speed_history.tsv"
    git -C "$R/bench/records" add gate_history.tsv speed_history.tsv && git -C "$R/bench/records" commit -q -m "a52c24a80e04 $sha: backfill (measured $(date +%Y-%m-%d) with the harness of $(git -C "$R" rev-parse --short HEAD))" || { echo "$sha: records commit failed"; exit 1; }
    printf '%s\n' "$row" | cut -f2,11,14-17
    ```

        - _Gates that check frozen or rarely changed code._ The seven `stage0c-*` gates (about 400 items) test a seed that changes only by a recorded fix (`AGENTS.md`). `mutation-self-test` builds four mutant compilers (about 90 s, the slowest gate) to test `mutation-check.sh` itself. Most of the 48 scenarios test our own scripts: runner-output, preflight-selftest, comment-noise-selftest and the like. Each could run only when its subject changed, plus always in `make preflight`.
        - _Work done twice._ The safety matrix runs whole-program and under zbuild (443 probes each, required by "two implementations tested against each other"). `test_checked.sh` reruns the whole suite. The reject differential's base compiler is rebuilt on every `preflight-changed` against the same base: cache it in `build/` keyed by the base commit. `selfhost-check` and the reject differential may each build a compiler from a clean tree.
        - _Redundant and obsolete tests._ Find the duplicates: same normalised ZIL, same diagnostic for the same construct, tests of retired features or of bugs whose code is gone (id:z0107).
        - _Fewer processes per test._ Each run test spawns zoril, zilc, qbe, as and ld. Measure fixed cost against compile time. Then weigh merging many run tests into one file, or a compiler mode that compiles several inputs in one process, against losing failure isolation. A `compile fail` or `EXPECT:` test cannot be merged (id:z0108).

        - _Progress output._ The current output looks hung during a long item: a gate prints only when it ends, and lines print in plan order, so one slow gate holds back every line after it. Show what is running as it starts, a heartbeat at least every 10 s, and fast items collapsed into one count line (id:z0110).

Some use `git ls-files` only to list files. Some build scratch repositories (`git init` in `test_build_info.sh`, `test_full_test_stamp.sh`, `dist_user_paths.sh`, `check_clean_tree.sh --selftest`, `check_stray_files.sh --selftest`). Inventory them, and keep git only where the thing under test is a git feature (id:z0111).
        - _The workflow rule itself._ `AGENTS.md` asks for `make test` and `make preflight-changed` on every change to `src/`, `stdlib/` or `tools/`, but does not say when within a task. Run them once, after the last code edit. A task-file-only or completion-note commit after a passing run reruns nothing (id:z0112's wording, once the tiers exist).
        - _The author and the reviewer run the same suites on the same tree._ A check-in's reviewer rightly reruns everything rather than take the author's word, so each safety task pays for its full verification twice. Results depend on inputs, not on who ran them: cache each item's verdict keyed by a hash of its inputs, which the reviewer computes from its own build. The reviewer then reruns a random sample, everything the change touched, and every failure, and treats any disagreement as a finding (id:z0113). The differential is the largest single cost and the easiest to key (id:z0114).
        - _Iterating on failures._ `make retest-failed` reruns only the items that failed last time, from `--results`. Fail-fast is the default while iterating.
