# Shared tests that are correct Zoril but outside the stage0-C dialect
# (doc/stage0-C/language_subset.md §3), or that expect a diagnostic this compiler does not
# produce (§1.6). They are out of scope for stage0-C: its runners neither run nor count them,
# as for any file outside a suite's directory. The self-hosted compiler's suites run them.
# One entry per line:
#   <path relative to the repository root>: <reason>
#
# The runners compile these files against the repository's `stdlib/`, not against the frozen
# `stage1/stdlib` (which only the bootstrap build of `stage1/` uses). A stdlib API that moved
# is therefore never a reason to list a file here: a gate that stops compiling a file after a
# stdlib change is reporting a stage0-C gap, to fix or to record in `tests/known_bugs.txt`.
# One runner, `test_error_locations.sh`, passes no include flags at all, so a test whose file
# imports a `stdlib/` module cannot get the diagnostic it annotates; those files are listed
# with the diagnostic they expect.
#
# Add an entry only for a dialect limit documented in language_subset.md §3 or a §1.6
# checker diagnostic. A stage0-C bug is not out of scope: fix it (with a test in
# tests/fixed_bugs/) or, if it is not a quick fix, list it in tests/known_bugs.txt, where it
# is reported as a skip until it is fixed.
